## Architecture & UI Trade-offs
- **Vanilla JS over Frameworks:** Assuming the strict zero-dependency and single-file target (`index.html`) requires bypassing heavy frontend frameworks (like React or Vue) in favor of Vanilla JavaScript and modern native DOM APIs (Web Components, View Transitions). This mirrors the architecture needed for highly portable, client-side web tools.
- **Local Storage Quotas:** Assuming standard browser `localStorage` limits (~5MB). To prevent quota exhaustion, the history array will function as a FIFO ring buffer capped at 100 entries. Larger preset libraries will rely on JSON export/import.
- **Tri-Mode AI Fallback:** Assuming the user prioritizes cost and privacy, the Dissector will attempt Mode 1 (In-Browser WebGPU) first, falling back to Mode 2 (Cloud APIs) only if the hardware fails to allocate sufficient VRAM.

## Tri-Mode AI Dissector — resolved spec conflicts
- **Mode 1 is an embedded offline taxonomy engine, not a downloaded LLM.** `FEATURE-MECHANICS.md` §7.1 calls for `@huggingface/transformers` with lazy-downloaded Qwen2.5-0.5B/SmolLM2 weights, but the owner's execution constraint (no external frameworks, no remote CDNs, single offline-capable `index.html`) takes precedence and makes multi-megabyte runtime weight downloads impossible. Mode 1 therefore ships as a deterministic, fully-embedded genre/attribute knowledge-base dissector (real logic, testable, zero network). The Universal AI Provider Interface keeps a provider slot so a true WebGPU LLM can be plugged in later if the constraint is relaxed. Token Probability Heatmap (feature #59) depends on local-LLM logits and is deferred with the same rationale.
- **Fallback order follows FEATURE-MECHANICS §7.3 (Cloud → Local), not the older note above** that said Mode 1 first — FEATURE-MECHANICS ranks higher in the document hierarchy. The user can still pin any single mode manually.
- **Network-call policy refined:** the "zero external references" rule forbids loading *code or assets* (scripts, styles, fonts, images, importScripts) from any URL — that stays absolute. User-initiated *data* calls required by the FDD (cloud inference APIs, `http://localhost:11434` Ollama) are permitted, restricted to: localhost URLs, plus cloud endpoints declared in the single `CLOUD_API_PRESETS` registry or entered by the user at runtime. `tests/verify-single-file.js` enforces exactly this. API keys entered in the UI are held in memory only — never persisted, matching the env-only secrets rule.

## Local-LLM Mode 1 upgrade & provider overhaul — owner-directed decisions (2026-08-25)
- **Opt-in, hash-pinned runtime download preserves the single-file promise.** The owner authorized runtime weight downloads for Mode 1. The ~450KB transformers.js runtime is likewise fetched only after an explicit consent click, from a URL pinned in `LOCAL_MODEL_SOURCES`, SHA-256-verified against a committed hash before execution. Nothing loads at boot; the app remains one file; vendoring was rejected on evidence (Chrome blocks module loads and sibling fetches from `file://`). `verify-single-file.js` policy v2 enforces exactly this ("one file; nothing loads until the user asks; runtime-fetched code is hash-pinned").
- **Default dissector mode = `local-llm`** (Qwen2.5-0.5B, per the owner's "most powerful of the ones already mentioned"); SmolLM2-360M is offered as a lighter alternative in the same picker (both are FDD-named). Until weights are downloaded, `local-llm` silently falls through to the instant taxonomy engine — no fake answers, no false "cloud busy" toasts. The taxonomy engine keeps the mode id `local`.
- **Auto chain order stays mechanics-§7.3-literal (cloud → local-llm → taxonomy).** The owner's "local AI default" is honored by the default *mode*; Auto remains the explicit "try everything" mode and keeps its tested contract.
- **Key persistence ships the device tier only** (AES-GCM ciphertext in IndexedDB, non-extractable CryptoKey in a separate store, auto-unlock — matching "users will hate re-entering keys"). The optional passphrase tier is reserved in the record shape and queued as a follow-up. Honest UI copy states the threat model: protects against casual storage inspection, not against code running in the same origin.
- **A remembered key arms Auto's cloud step automatically** — that is the convenience the owner asked for — with a permanently visible "cloud armed: <provider>" indicator and one-click disarm in the dissector config. A blank vault keeps Auto fully offline as today.
- **Gemini preset dropped; Groq folds into the generic OpenAI-compatible preset** as a base-URL suggestion — per the owner's "stick to OpenAI-compatible ones and OpenRouter". OpenRouter is first-class (attribution headers, optional user-triggered model-list fetch).

## Tooling & Environment
- **`.mcp.json` env-var syntax:** The directive (`docs/SUNO-AI-AGENT-DIRECTIVE.md` §1.1) shows Windows `%VAR%` syntax inside `.mcp.json`. Claude Code expands `${VAR}` (not `%VAR%`) in `.mcp.json` values, so `${STITCH_API_KEY}` / `${GEMINI_API_KEY}` are used instead. Secrets still live only in the environment; nothing is written to disk.
- **GATE 0 sequencing:** The GATE 0 items "Autocorrelation DSP unit test passing" and "character limiter unit test passing" can only pass once the YIN worker and prompt compiler exist (queue tasks 2–3 and 8). The test harness is scaffolded first with those suites registered as explicit `todo` entries; the nightly runner fails on *unexpected* failures but reports `todo` suites honestly. GATE 0 closes at the earliest moment the implementations land.
- **E2E without external frameworks:** The overnight E2E suite is pure Node (no Playwright/Puppeteer dependency) — it extracts the inline app/worker scripts from `index.html` by marker ID and executes them in `node:vm` sandboxes with minimal DOM/Worker stubs. This keeps the repo zero-dependency while still executing the real production code paths (no simulated logic).
